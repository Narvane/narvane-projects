# Each Project Has Description

## Purpose

This definition establishes that:

> **A project is only considered defined if it has a clear and explicit description.**

The description ensures that the project communicates its purpose, intent, and direction.

---

## Definition

A project **has a description** when:

* There is a dedicated `.md` file at the root of the project
* This file clearly explains what the project is
* It describes the idea, purpose, and intended direction

---

## Requirements

To satisfy this definition, each project must:

* Include a description file at its root (e.g., `README.md`, `definition.md`, or equivalent)
* Clearly state:

  * What the project is
  * Why it exists
  * What it aims to achieve

The description should provide enough context so that:

> **Someone can understand the project without exploring its internal structure.**

---

## Failure Conditions

A project does **not** meet this definition if:

* There is no description file
* The description is empty or unclear
* The purpose of the project cannot be understood from the file

---

## Final Note

> **A project without a description has no declared identity — and therefore cannot be considered defined.**
